# Architecture & Integration Decisions (DECISIONS.md)

## D-01: Monorepo Base & Conflict Resolution (`Turbostarter` vs `xb3sox/nextjob`)

**Context:**
We are integrating the existing `xb3sox/nextjob` repository implementation into the new `Turbostarter` monorepo base (`apps/web`, `apps/extension`, `apps/mobile`, `packages/*`). Where conflicts exist, we compare both and pick the superior design.

| Layer / Capability | `Turbostarter` (Current Base) | `xb3sox/nextjob` (Prior Repo) | Decision & Rationale |
| --- | --- | --- | --- |
| **Web Framework** | Next.js 16.4 App Router (`apps/web/src/app/[locale]`) with RSC, Suspense, `proxy.ts`, Hono RPC (`hc<AppRouter>`) | Vite + React 18 SPA (`src/pages/*`) with `react-router-dom` | **Pick Turbostarter (Next.js 16.4 App Router).** Matches target architecture in `docs/TECH.md` and Section 8 Reference Stack. Port NextJob screens (`Today`, `Find Jobs`, `My Career`, `Applications`) and components (`JobCard`, tailoring review, tracker) into `apps/web`. |
| **API Layer** | `@workspace/api` using Hono with end-to-end typed RPC client (`hc<AppRouter>`), Zod validation middleware (`validate`), and Better Auth session guard (`enforceAuth`) | Fastify + Express + unmounted services in `packages/api` | **Pick Turbostarter (`@workspace/api` Hono) + Port NextJob Domain Engines.** Hono gives zero-boilerplate typed RPC directly inside Next.js `/api/[...route]` and standalone workers. Mount NextJob domain modules (`/api/career`, `/api/jobs`, `/api/tailoring`, `/api/applications`) onto `appRouter`. |
| **Authentication & Tenancy** | `@workspace/auth` (Better Auth + Drizzle Postgres schema: `user`, `session`, `account`, `organization`, `member`, `twoFactor`, `passkey`) | Supabase Auth on client + custom PBKDF2 auth in `packages/api/src/auth` | **Pick Turbostarter (`@workspace/auth` Better Auth).** Production-ready, self-hostable, open-source, already wired into Web/Mobile/API/DB. Enforce strict per-user (`userId`) ownership and optional organization isolation on every NextJob query. |
| **Database & ORM** | `@workspace/db` (Drizzle ORM + PostgreSQL, `snake_case` casing, `user.id` text PK) | `packages/api/src/db/schema.ts` (7 tables) + in-memory `Map` stores in domain services | **Merge into `@workspace/db`.** Extend `@workspace/db/src/schema/` with NextJob domain tables (`career_claims`, `career_evidence`, `career_revisions`, `career_preferences`, `jobs`, `job_sources`, `saved_jobs`, `eligibility_assessments`, `job_matches`, `tailored_documents`, `applications`, `application_events`, `submission_receipts`, `reusable_answers`, `approvals`, `audit_events`) referencing `user.id`, with repository fallback so unit tests and DB-backed runtime both work seamlessly. |
| **Career Domain Logic** | None (generic SaaS starter) | Rich, tested engines: `EligibilityEngineService` (10 check types, 114 eval cases, 0% FP), `MatchingEngineService` (7 weighted factors + explainability), `JobNormalizationService`, `JobDeduplicationService`, `TailoringEngine` (evidence-constrained, 64 eval cases), `ApplicationStateMachine` (23 states + guards), `SubmissionReceipt` (SHA-256 content-hashed receipts), `PolicyEngine` & `ApprovalService` (risk tiers & payload hash binding), `PII Redaction` | **Pick `xb3sox/nextjob` Domain Engines.** Port and consolidate these battle-tested, pure TypeScript engines into `@workspace/career` (or domain modules in `@workspace/api` & `@workspace/db`) with full unit and eval test suites preserved. |
| **Localization & RTL** | `@workspace/i18n` (`i18next`, route-based `[locale]`, currently `en`, `es`) | `packages/shared/src/i18n` (`isRTL`, `getLanguageDirection`, `ar`, `en`, `es`, `he`) | **Combine Both.** Add `ar` (Arabic) to `@workspace/i18n` locales (`["en", "es", "ar"]`), add full Arabic translations, and wire `dir={getLanguageDirection(locale)}` onto `<html lang={locale} dir={dir}>` in `apps/web/src/modules/common/layout/base.tsx`. |
| **Billing** | `@workspace/billing` (Stripe/LemonSqueezy/Polar scaffold) | `packages/api/src/billing` (in-memory mock) | **Keep Turbostarter scaffold dormant for P0.** Per Section 2 ("Do not implement billing in P0"), hide billing upsells from the primary NextJob P0 candidate workflow while preserving workspace package integrity. |
| **Workflow & Background Execution** | Lightweight modular monolith | Temporal SDK dependency (requires external Temporal server cluster) | **Pick Lightweight Modular Monolith (Section 8).** Section 8 explicitly specifies: "Avoid initially: Microservices, Kubernetes, Multiple workflow engines... Introduce infrastructure only when justified by actual requirements." Use deterministic state-machine transitions (`ApplicationStateMachine`) + idempotent DB-backed/repository execution and SHA-256 receipts (`SubmissionReceipt`). |

## D-02: Product Research & Competitor Evaluation

- **Simplify**: Strong browser autofill UX; weak on evidence provenance and fabricates generic AI answers without trace. *Adoption*: fast autofill profile schema. *Differentiation*: strict claim-to-evidence traceability (`evidenceClaimIds`).
- **Teal**: Good application tracker + resume builder; cluttered analytics-heavy dashboard and paywalled keyword matching. *Adoption*: unified tracker + resume studio. *Differentiation*: action-first "Today" screen ("Prioritize actions over analytics") and deterministic eligibility gate before match ranking.
- **Huntr**: Kanban board for applications; manual data entry heavy. *Adoption*: clear lifecycle stage grouping. *Differentiation*: 12 explicit candidate-facing statuses distinguishing `Submitting`, `Submission Uncertain` (`SUBMITTED_UNVERIFIED`), and `Confirmed` (`SUBMITTED_VERIFIED`) backed by cryptographic SHA-256 receipts.
- **Reactive Resume / JSON Resume**: Great open-source schema and portable JSON export/import; lacks job discovery, eligibility checking, and application state tracking. *Adoption*: first-class JSON Resume import/export compatibility in P0-02 and P0-03. *Differentiation*: full loop from import → verification → discovery → fit analysis → tailoring → export → receipt-verified tracking.

## D-03: Visual Identity & Brand System

- **Brand Name**: NextJob (Note: external trademark/domain availability must be verified by legal counsel before commercial publication; marked as assumption/advisory per Section 4).
- **Tagline**: *One Profile. Every Opportunity. Less Work.*
- **Visual Direction**: High-contrast, calm editorial workspace ("Ink & Paper" with "Moss / Emerald" verification accents from `xb3sox/nextjob`, harmonized with `@workspace/ui-web` semantic tokens for full light/dark theme and WCAG 2.2 AA contrast compliance).
- **Typography**: `Geist` (sans), `Source Serif 4` (editorial display headings), `Geist Mono` (tabular numbers, hashes, receipts, scores), with clean Arabic (`dir="rtl"`) glyph rendering.
- **Four Main Screens (Section 5)**:
  1. **Today** (`/dashboard`): Daily action center — recommended eligible jobs, applications ready for approval, pending claim verifications, recruiter responses, interviews, and follow-up reminders.
  2. **Find Jobs** (`/dashboard/jobs`): Live + permitted public job discovery connector (e.g., Remotive / Lever / Greenhouse public feeds with resilient fallback + deduplication), search/filters, and 5-question Job Fit card (*Why does this match me? What requirements do I meet? What am I missing? Is the opportunity credible? What happens when I apply?*).
  3. **My Career** (`/dashboard/career`): Authoritative career profile (Summary, Experience, Education, Skills, Projects, Certifications, Achievements, Preferences, Reusable Answers), CV/JSON Resume/Text import with conflict detection, verification queue (`verified` / `unverified` / `pending_review`), revision history, and conversational AI career update proposals requiring explicit user approval.
  4. **Applications** (`/dashboard/applications`): Pipeline tracker across all 12 required states (`Saved`, `Preparing`, `Needs Approval`, `Ready`, `Submitting`, `Submission Uncertain`, `Confirmed`, `Interview`, `Offer`, `Rejected`, `Withdrawn`, `Failed`), integrated Tailored CV/Resume Builder with live preview, HTML/PDF/DOCX/JSON export, and cryptographic submission receipt inspector.
  - **Persistent AI Career Assistant**: Accessible across dashboard screens to propose structured profile updates, explain fit gaps, and draft answers — never modifying authoritative data without user review and approval.
